# Washi PDF

[English](README.md) | **日本語**

**オンライン版：[washipdf.com](https://washipdf.com)**（PWA としてインストール可）／ **ダウンロード版：[Releases](https://github.com/chemlsci/washipdf/releases)**

**HTMLファイル1つ**で動くPDF編集ツールです。ダウンロードしたファイル（例：`washi-pdf-v1.0.0-ja.html`）をダブルクリックするとブラウザーで開き、そのまま使えます。インストールも管理者権限もサーバーもいりません。PDF はブラウザーの中だけで処理され、どこにも送られません。ダウンロード版は一切通信しません（Web 版は、アプリ本体・更新（押したときだけ）・文字認識のデータを washipdf.com から受け取るだけです）。加えて Content-Security-Policy（`default-src 'none'; connect-src 'none'`）で、外部への接続（fetch / XHR / WebSocket）、外部のスクリプト・画像・フォントの読み込み、フォーム送信をブラウザーに止めさせています。悪意ある PDF や不具合でアプリ内に不正なコードが紛れ込んでも、通常の方法では外へ送れません（多層防御であり、絶対の保証ではありません。CSP では止められない手段のうち、WebRTC はアプリの起動時に使えなくし、アプリの外のページへの移動は、移る前に尋ねます。移動の確認は、移動を見張る仕組み（Navigation API）のあるブラウザーで働き、無いブラウザーでは新しい窓を開く動作だけを見張ります）。ファイル自体のすり替えは、Releases の SHA-256 で確認できます。

**CDN にも頼りません。** pdf.js・フォント・WASM・CMap まで全部を HTML 1 個に同梱しているので、使うときに外部からコードを取ってくることがありません。CDN から部品を読み込む方式は、配信元やその元のパッケージが乗っ取られると、正規の URL から改ざんされたコードがそのまま届きます（2024 年の polyfill.io 事件など）。また CDN 側には「いつ・どの IP から・どのツールを使ったか」が残ります。Washi PDF は**配布物を一度 SHA-256 で確認すれば、以後はずっと同じ中身**で動きます（CDN 方式は「開くたびに配信元を信頼する」、Washi PDF は「一度確認して固定」）。

日本語PDFの **既存テキストを「上から隠す」のではなく本当に書き換える** ことを目標にしています（書き換えられる行では、検索・コピーで元の文字が出てきません。上から隠すことしかできない行は、編集の前にそう表示します）。

## できること

| --- | --- |
| 既存テキストの編集 | 行または段落をクリックして書き換え。複数行をドラッグで囲んでまとめて書き換えることもできます（スマホでは「範囲」モードのとき）。囲んだ直後は候補の状態で、行をタップして足し引きしてから確定します。2 段組みでは囲みの中心に近い段だけを採り、同じ段落の行は間を埋めます。元の文字描画命令を PDF から削除し、新しい文字を書き込みます。禁則処理付きの箱内リフロー、収まらないときの自動縮小と警告、元フォントの再利用（無い文字は同梱の日本語フォントで代替） |

| ページ整理 | 複数PDFの結合、並び替え（ドラッグ／ボタン。スマホは長押しで掴んで動かす）、回転、削除、複製、白紙ページの挿入、途中へのPDF挿入 |

| 文書全体 | ページ番号・Bates、ヘッダー／フッター、透かし、トリミング、サイズ変更、逆順・交互結合、白紙除去、文書情報の編集・除去、画像／テキスト／Markdown への書き出し |
| まとめて処理 | 複数の PDF に、圧縮・ページ番号・透かし・個人情報の墨消し・文書情報（作成者・作成ソフトなど）の削除・パスワードをまとめて行い、ZIP でダウンロード |
| 圧縮 | 画像を表示に必要な解像度（dpi 指定）まで縮小して JPEG で再圧縮（部品の中の画像も対象。必要な解像度以下でも、高品質で保存された JPEG は指定の品質で圧縮し直す）。グレースケール化も可。あわせて、見た目を変えない処理を行います：丸ごと埋め込まれたフォント（「Microsoft Print to PDF」などの出力に多い）から使っていない字を除く、重複データの統合、圧縮のやり直し、表示に使われない付随データ（個別のメタデータ・ほかのソフトの編集用データ・ページの縮小画像）の除去。「画像は圧縮しない」を選ぶと、見た目を変えない処理だけを行います。実際の公開文書 171 件の合計では、見た目を変えない処理だけで約 11%、標準の設定（150dpi・品質 80）で約 28% 小さくなりました（文書によって 0〜83%。半数の文書は 8% 未満で、効果は大きな画像や丸ごと埋め込まれたフォントを含む文書に偏ります）。スキャンした書類向けに、画像を白黒 2 値（1 ビット、300dpi まで、ファクス方式 G4）にする選択肢もあります（既定はオフ。写真や色は失われるので、適用前にプレビューを拡大して確かめられます）。JBIG2 / JPEG 2000 での再圧縮は行いません |
| グレースケール化 | 文字・図形・画像・注釈の色をすべて灰色にして保存（特色・パターンはそのまま） |
| 文字認識（OCR）※ Web 版のみ | スキャンした（画像だけの）ページの文字を読み取り、見えない文字としてページに重ねる。見た目は変わらず、検索・選択・コピーと、語を探しての墨消しができるようになる。日本語（縦書きも）・英語・中国語・韓国語など 21 言語。認識は端末の中で行い、PDF や画像は送らない。認識のエンジン（Tesseract）と言語データは大きいので、ダウンロード用の HTML には入れず、Web 版が使うときに同じサイトから読み込む |
| 面付け | N-up（2・4・6・8・9・16 ページ／枚）、中綴じ小冊子、右綴じ、用紙・余白の指定 |
| しおり・添付 | しおり（目次）の引き継ぎ・追加・階層編集、添付ファイルの一覧・追加・取り出し |
| 文書の比較 | いまの文書と別の PDF を比較。ページの追加・削除・入れ替えを見分けて対応づけ、変わった語・文字にページの上で色を付ける（改行の位置だけの違い、空白・全角半角だけの違いも見分ける）。図・画像などの違いは赤枠（上で行が増えて下がずれても、ずれただけの所は違いにしない）。拡大して見られ、違いの一覧からその場所へ移れる。注釈付き PDF・いまの文書への報告の挿入・Markdown に書き出せる。スキャンした紙は、ずれや傾きを合わせてから比べる |
| パスワード保護 | RC4 40/128・AES-128・AES-256 の PDF をパスワードで開いて編集（解除）。保存時に AES-256（または RC4 128）で保護し、閲覧・所有者パスワードと印刷・変更・コピー・注釈の権限を設定 |
| 保存・共有・印刷 | 保存ボタンの横のメニューから、名前を付けて保存（対応ブラウザーでは保存先を選び、以後の保存は同じファイルへ）、開いた元のファイルへの上書き保存（Chrome / Edge で、ファイルを選ぶ・ドロップする・「Washi PDF で開く」で開いたとき。確認あり）、共有シート（スマホなど対応環境）、印刷（内蔵の PDF 表示で印刷。できないブラウザーでは別のタブで開く）。保存した PDF は、ファイルに書き込む前に開き直して確かめます（開けなければファイルには触れず、ダウンロードを勧めます）。上書きは確認してから行い、開いたあとにほかのアプリでファイルが変わっていれば知らせます |
| その他 | 保存の前に変更内容の一覧を確認、ページを続けてスクロールして表示、ページの幅に合わせる（PC の既定）／ページ全体を表示、画面の明るさ（明るい・暗い・端末に従う）、元に戻す／やり直す（何を戻すかをボタンに表示）、? でショートカットの一覧、Ctrl+F で検索、Ctrl+P で印刷、Ctrl+S で保存、ズーム（ピンチ・Ctrl＋ホイール・Ctrl +/−/0）、ページ整理のキー操作（Ctrl+A・Delete・Esc）、ツールの絞り込み検索、UI は 20 言語（日本語・英語・中国語簡体／繁体・韓国語・スペイン語・ポルトガル語・フランス語・ドイツ語・イタリア語・ロシア語・トルコ語・インドネシア語・ベトナム語・タイ語・ヒンディー語・ベンガル語・アラビア語・ウルドゥー語・ペルシア語。右から左の言語にも対応） |

対応ブラウザー：Chrome / Edge / Firefox / Safari の最新版。CI では、Chromium で編集の流れ一式を、Firefox と WebKit（Safari 相当）で一巡の操作（開く・文字の書き換え・全ツール・保存）を、PC とスマホの画面幅で確かめています。iPhone・Android の実機での網羅的な確認はまだ行っていません（不具合の報告を歓迎します）。

## 文字の種類ごとの対応状況

開く・表示・ページの整理・注釈・**範囲を指定しての墨消し**・文書全体の機能は、どの言語の PDF でも使えます。文字の種類で差が出るのは、**PDF に元からある文字の書き換え**と、**語を探しての置換・墨消し**です。

| PDF の中の文字 | 表示・ページ操作・注釈・範囲指定の墨消し | 既存文字の書き換え | 語を探して置換 | 語を探して墨消し | 新しい文字の追加 |
| --- | --- | --- | --- | --- | --- |
| 日本語・中国語・韓国語（横書き） | ✅ | ✅ | ✅ | ✅ | ✅（その字のフォントを持つ版） |
| 日本語の縦書き | ✅ | ✅（同じ字数以内はその場で。増えるときは縮小して収める） | ✅ | ⚠️ 列全体 | ✅ |
| ラテン文字（英語・欧州の各言語・ベトナム語など）、キリル文字、ギリシャ文字 | ✅ | ✅ | ✅ | ✅ | ✅ |
| タイ文字 | ✅ | ✅ | ✅ | ✅ 語の位置で。字形と対応が取れない行は行全体 | ✅（その字のフォントを持つ版：日本語版・英語版・全部入り） |
| アラビア文字（アラビア語・ペルシア語・ウルドゥー語）、ヘブライ文字 | ✅ | ⚠️ 語単位：変えた語だけを同梱フォントで書き、ほかの語は元の字形のまま（行の中の数字・欧文は、元のフォントに字があればそのフォントで） | ⚠️ 同上 | ✅ 語の単位で。字形と対応が取れない行は行全体 | ✅（その字のフォントを持つ版：日本語版・英語版・全部入り） |
| インド系の文字（ヒンディー語・ベンガル語・グジャラート語・パンジャブ語など） | ✅ | ⚠️ 語単位：変えた語だけを同梱フォントで書き、ほかは元の字形のまま（新しい語を書けるのはヒンディー語などのデーヴァナーガリーとベンガル語。そのほかは語の削除や、別の文字での置き換え） | ⚠️ 同上（語が見つかる場合。下記） | ✅ 語の位置で（語が見つかる場合）。字形と対応が取れない行は行全体 | ✅ ヒンディー語・ベンガル語 ・ ❌ そのほか |
| ラオス・クメール・ミャンマー・チベット文字 | ✅ | ⚠️ 上書きのみ | ❌ | ❌ 墨消しツールで範囲を指定 | ❌ |

- **上書きのみ**：元の文字を隠して、その上に新しい文字を書きます。元の文字のデータはファイルに残るので、消す必要があるときは墨消しを使ってください。
- 制限の理由：これらの文字は前後の字で形が変わり、字形が見た目の順に並ぶため、PDF の中の文字と字形を確実には対応付けられません。1 字ずつ書き直すと、字のつながりが崩れたり字が欠けたりします。
- **語単位**（インド系の文字と、どの文字でも「文字が割り当てられていない字形」を少し含む行）：こうした行の文字列は、PDF に入っている字形の並びそのままで、入力するときのつづりとは違います（母音記号が子音の前に来る、結合文字に文字が割り当てられていない、など）。そこで、実際に変えた語だけを同梱フォントで正しい形に整えて書き、行のほかの部分には触れません。語はまるごと打ち直してください。編集中のページには、保存結果そのものが表示されます。この方法で扱えない行は元のまま残し、その旨を知らせます。検索は、入力したつづりを PDF の中の並びにも合わせて探します（子音の前に置かれる母音記号に対応）。ただし、文字が割り当てられていない結合文字を含む語は見つかりません。その場合は墨消しツールで範囲を指定してください。
- どの文字でも、足した字が文書のフォントに無いときは同じ扱いです：その語だけ（日本語・中国語・韓国語ではその字だけ）が同梱フォントになり、行のほかの部分は元のフォントのままです。
- アラビア文字・ヘブライ文字：PDF の中では、字形は見た目の順（左から右）に並んでいます。行の文字列は、字形の位置から語を切り出し、語を読む順に並べて組み立てます（かっこや文末の句点の向きも、読む順に直します）。書き換えるときは、変えた語だけを同梱フォントで書き、ほかの語は元の字形のまま、行の進む向き（右から左の行なら左）へ幅の差だけずらします。同梱フォントの字の大きさは、元の行の語の幅に合わせます。行に収まらないときは行全体を横に縮めます。数字や欧文の語句が続く所は、その続きをまとめて書き直します。欧文の長い語句が両端にある行では、行の向きを取り違えて語の並びが入れ替わって表示されることがあります（編集中のページには保存結果がそのまま出るので、確かめられます）。フォーム（部品）の中の行と、字形から文字列を組み立てられない行は、上書きのみです。
- タイ文字：母音・声調の記号は別の字形で、下の字によって高さが変わります。書き換えた語には、同じページでその組み合わせに使われている記号の形を使います。ページに無い組み合わせはフォントの標準の記号になるため、元の組版より少し上下にずれることがあります。
- 墨消しを含む保存のあとは、保存したファイルを読み直し、消した語が残っていれば知らせます。
- 実際の公開文書で確かめた言語：日本語、英語、中国語（簡体・繁体）、韓国語、ロシア語、ベトナム語、スペイン語、フランス語、イタリア語、ポルトガル語、ポーランド語、タガログ語、ハイチ・クレオール語、アラビア語、ペルシア語、ウルドゥー語、ベンガル語、グジャラート語、パンジャブ語、クメール語、タイ語、ヒンディー語。

## スマホ・アプリとして使う（PWA）

[washipdf.com](https://washipdf.com) の各版は **PWA** に対応しています。ブラウザーのメニューから「アプリをインストール」/「ホーム画面に追加」を選ぶと、アプリのように起動でき、一度開けば **オフラインでも動作** します（Service Worker がアプリ本体をキャッシュします）。版ごとに別のアプリとしてインストールされます。

**スマホでダウンロード版（HTML ファイル 1 個）を使う場合**：Android では、ファイルアプリでその HTML を選び「Chrome で開く」を選んでください。アドレス欄に `file://` を直接入力する方法や、「HTML ビューア」で開く方法では、たいてい動きません（端末によって挙動が違います）。うまく開けないときは、上の Web 版（インストールすればオフラインでも動きます）を使ってください。iPhone / iPad は Web 版をおすすめします。

パソコンの Chrome / Edge でインストールすると、**PDF ファイルを右クリック →「プログラムから開く」で Washi PDF を選べます**（既定のアプリにも設定可能。File Handling API）。Firefox・Safari、スマホは非対応です。

インストール後も **外部への接続は禁止されたまま** です。PWA 版の Content-Security-Policy も `connect-src 'none'` を維持しており、取得するのは同じ配信元の静的ファイルだけです（アプリ本体・アイコン、「更新を確認」を押したときに新しい版の有無を見るための小さなファイル、文字認識を使った場合はそのエンジンと言語データ）。アプリが自分から新しい版を確かめに行くことはなく、取り込むのも、利用者が更新を選んだときだけです。利用者の PDF は送りません。配布用の単一 HTML ファイル（Releases 版）は PWA 要素を含まず、ローカルで完結します。

### 通信のまとめ

| 使い方 | サイトから受け取るもの | 送るもの |
| --- | --- | --- |
| Web 版をブラウザーで開く | アプリ本体（最初の 1 回）、新しい版（「更新を確認」を押したときだけ）、文字認識の部品（使うとき） | なし（PDF の中身・ファイル名・編集内容は端末の外に出ません） |
| Web 版をアプリとして入れる（PWA） | 上と同じ。起動は、端末に保存した版から | なし |
| ダウンロード版（HTML ファイル） | なし（通信しません） | なし |

配信元に分かるのは、ファイルを取りに来た記録（IP アドレス・日時・どのファイルか）だけです。ブラウザー自身が、保存したアプリの管理のために Service Worker のファイルを読み直すことがあります。 Service Worker（`sw.js`）は、このリポジトリではなくサイトの組み立てで作っています。各版の `https://washipdf.com/app/<版>/sw.js`（例：`/app/ja/sw.js`）で誰でも中身を読めます。同じサイトにあるアプリ自身のファイルを保存して返すだけです。

### Web に置いて使う場合の性質

- **PDF の中身は送られません。** CSP（`connect-src 'none'`）はそのまま効くので、配信の仕方に関係なく、アプリからほかのサーバーへの接続はブラウザーが止めます
- **第三者の CDN は関与しません。** 読み込むのは配信元の静的ファイルだけです
- **配信元が知り得るのは「アプリを開いた」記録（IP・時刻）だけ** です。文字認識（OCR）を除く全機能が 1 ファイルに入っているので、どのツールを使ったかは配信元にも分かりません。文字認識だけは、使うときにエンジンと言語データを配信元から読み込むので、使ったことと選んだ言語が配信元に分かります（PDF や画像は送りません）
- ホスティング側が外部の解析用スクリプトなどを自動で差し込んでも、CSP により、ほかのサイトからの読み込みと接続は止まります（文字認識を使える版は、同じ配信元のプログラムの読み込みだけを許しています：`script-src 'self'`）
- **注意：配信元を信頼する点は CDN 方式と同じです。** リポジトリや配信アカウントが乗っ取られて HTML ごと差し替えられると、CSP も含めて書き換えられます。PWA は一度入れればキャッシュした版で動きますが、更新のときには新しい版を信頼することになります

このため、**機密文書には Releases 版（SHA-256 を確認したローカルファイル）** をおすすめします。組織の中で使う場合は、SHA-256 を確認したファイルを組織内のサーバーに置けば、外部の配信元を信頼せずに済みます。

## 既存テキスト編集のしくみ

1. **解析**：pdf.js でページ内の文字の位置を取り、同じ行の断片を結合します。同時に、自前のトークナイザ（`src/lib/contentStream.ts`）でコンテンツストリームを解釈し、文字を描く命令（`Tj` / `TJ` / `'` / `"`）ごとに位置・進み量・色・文字状態を計算して（`src/lib/textOps.ts`）、行と命令を対応付けます（`src/lib/textRuns.ts`）。表のセルや段組みは BT ブロックと列の左端で区別します。
2. **編集**：クリックした行（または段落）の文字を入力します。段落は同じ幅・行送りの連続行から検出します。
3. **保存**（`src/lib/textEdit.ts`）：
   - 該当する命令をコンテンツストリームから取り除きます。同じ行で後ろに続く命令がある場合は、進み量だけを残す `[-幅] TJ` に置き換えて位置がずれないようにします。
   - 元フォントで新しい文字が書けるか判定します（ToUnicode の逆引き、埋め込み TrueType の cmap）。書けない文字があれば、同梱フォントのうち文字の種類に合うもの（OFL）に切り替えます。
   - 元の幅の中で折り返します（`src/lib/layout.ts`）。行頭禁則（、。」ー など）・行末禁則（「（ など）・ぶら下げ・欧文の単語単位の折り返しに対応。元の行数に収まらなければ文字サイズを 5% ずつ（60% まで）縮小し、それでも無理なら保存時に警告します。文字間隔（Tc）・単語間隔（Tw）・水平拡大率（Tz）・色は元の指定を再現します。

### 制約（現時点）

- 透明な文字（OCR 層）、クリッピングに使われる文字、入れ子が 6 段を超えるフォーム XObject の中の文字は実編集できません（従来の「上から隠して書き直す」方式になります。橙色の枠で表示）。フォーム XObject の中の文字・画像・図形は、その呼び出しだけを複製して書き換えます（同じフォームを使う他のページは変わりません）。
- 縦書きの流し込みは、隣り合う列として検出できた段落の中だけです。同梱フォントで書くときは 1 文字ずつ積み、欧文・長音・括弧は回転、句読点は右上、1〜3 桁の数字は縦中横にします（ルビ・圏点などの組版は対象外）。
- 墨消しで図形を切り取れないのは、クリップを伴うパスとシェーディングです（見えなくするだけでデータは残り、保存時に警告します）。模様（タイリングパターン）や透明度のマスクの中にある文字・画像も消せません（見えなくなるだけです。保存時に警告し、「確認しました」とは表示しません）。
- 墨消しした字の手がかりも取り除きます：消した字を囲む読み（/ActualText・代替テキスト）、ページの縮小画像、ほかのソフトの編集用データ、消した字にだけ使われていたフォント。ほかの字と共用のフォントからは、どこでも使われなくなった字の対応表・幅・字の形を取り除きます（字の形を取り除けるのは TrueType と Type3 のフォントです。CFF 形式のフォントでは、「その字がフォントに入っていること」が字の形として残ります）。消した語を含むページ番号のラベルとレイヤーの名前も取り除きます。消した範囲の幅（おおよそ何字ぶんか）は、後ろの文字を動かさないために残ります。
- このアプリで書き換えた行や足した文字・画像に、墨消しの範囲が一部だけ掛かっているときは、保存を止めて知らせます（範囲の下の文字がファイルに残るため。文字から消すか、範囲を全体に広げてください）。範囲にすっかり入っているものは、保存のときに取り除きます。
- 元の PDF に入っている JavaScript・外部プログラムの起動・フォームの送信・ほかのファイルを開く動作（ページを開いたとき・リンクやボタンを押したときの動作）と、http(s)・mailto・tel 以外のアドレスへのリンクは、保存のときに取り除きます。墨消しした語が文書情報・しおり・添付ファイル名・注釈・他のページに残っていれば保存時に警告します。
- 編集中の内容（開いた PDF そのものと編集）はブラウザーの IndexedDB に自動保存され、次回開いたときに復元できます（Web 版。ダウンロードした HTML ファイルで使うときは、「このソフトについて」で入れるまで自動保存しません）。文書を閉じたときと、最後の自動保存から 7 日を過ぎたあと次にアプリを開いたときに消えます（それまではブラウザーの中に残ります）。パスワード付きで開いた PDF と、400 MB を超える文書は自動保存しません。自動保存するのは 1 つのタブだけです（ほかのタブではそう表示します）。パスワードは自動保存しないので、復元したあとはパスワード保護を設定し直してください。同じブラウザーを使う人は復元の画面から内容を見られます。HTML ファイルを直接開いて使う場合は、同じブラウザーで開いたほかの HTML ファイルからも読めることがあります。共用のパソコンや取り扱いに注意が要る文書では、「このソフトについて」で自動保存を切ってください。
- 電子署名付きの PDF は開けますが、編集して保存すると署名は無効になります（読み込み時と保存時に警告します）。
- 段落をまたぐ・ページをまたぐ流し込みはしません（下の内容を押し下げません）。
- 描画の命令がとても多いページ（数百万回の描画、数十 MB の内容、部品の呼び出しが何重にも繰り返されるもの）では、動きが非常に遅くなったり、タブが止まったりすることがあります（特にスマホ）。拡大してブラウザーが描ける画像の大きさを超えるときは、解像度を下げて描きます（白紙にはならず、少しぼやけます）。
- 縦書きとして書き換えられるのは、縦書き用の指定（Identity-V など）で書かれた列です。横書き用のフォントで 1 字ずつ縦に並べた縦書き（ブラウザーの印刷や LibreOffice が出す形）は、列として正しくまとまらないことがあります（墨消し・注釈・ページの操作は使えます）。
- 横倒しのまま保存されているページを、このアプリで回して正立させた直後は、そのページの文字を書き換えられません。一度保存して開き直すと、書き換えられます。
- 文書の比較で、文字の情報が無いページ（スキャンした紙）は見た目だけで比べます。数文字の語の変更は見つけられないことがあります（文字の情報を付けた PDF どうしなら、文字単位で比べられます）。41 ページ以上の文書では、図や画像の違いを縮小した見た目でざっと調べるため、ごく小さな違いを見落とすことがあります（1,000 ページを超えると、表示中のページだけ調べます）。内容ごと縮小・拡大した PDF は、見た目の比較では全面が違いになります。文字のあるページどうしでは、文字は文字として比べるので、文字の色や位置だけの変更（文字そのものは同じ）は違いとして出ません。ページの上の色付けの位置は、文字の幅から求めたおおよその位置です。
- PDF/A などの規格への適合の表示は、保存した PDF には引き継ぎません（編集後の文書が規格に合っているとは限らないため）。レイヤーの表示・非表示、文書内リンク、しおりの位置、開き方の指定は引き継ぎます。
- 定義済み CMap（`90ms-RKSJ-H` など）を使う非埋め込み和文フォントは表示・抽出はできますが、書き込みは同梱フォントになります。
- 公開鍵方式（証明書）で暗号化された PDF は開けません。
- アラビア語・ヘブライ語の字形は表示順（左から右）に並べて書きます（多くの製作ソフトと同じ）。読む順の文字列を `/ActualText` で添えているので、これを読むソフトでは正しい順で取り出せます。読まないソフトでは、語の中の字の順が逆に見えることがあります。

## 1ファイル化のしくみ

`scripts/build.mjs`（esbuild）で次のものを1つの HTML にまとめています。埋め込むデータ（本体・ワーカー・CMap と WASM・フォント）は gzip で縮めてから base64 にしているので、HTML はフォントをそのまま入れた場合の半分ほどの大きさです（開くときに戻します）。

| 中身 | 埋め込み方 |
| --- | --- |
| アプリ本体（React / pdf-lib / pdf.js） | 縮めて埋め込み、起動時にブラウザーの展開の機能（DecompressionStream）で戻して Blob から読み込む |
| pdf.js のワーカー | `file://` でも動く通常スクリプト形式に変換して埋め込む |
| pdf.js の定義済み CMap（日中韓すべて）と WASM（JPEG 2000 / JBIG2 / ICC） | 1 つのバイト列にまとめて埋め込み、`BinaryDataFactory` で外部通信なしに供給 |
| フォントパック（`assets/fonts/fonts.json`。`--fonts=ja,latin` で選択） | 縮めて埋め込み、使う時に初めて戻す（その版の既定のフォントは、画面が出た直後に前もって戻す）。保存時は使った文字の形だけを残して PDF に入れる（`src/lib/ttfSubset.ts`）。文字の範囲から自動でフォントを選ぶ |
| `NOTICE` / `THIRD_PARTY_LICENSES` | アプリ内「このソフトについて」から参照 |

### フォントパックとビルドの種類

| ビルド | コマンド | 同梱フォント | サイズ |

複数のパックを `--fonts=ja,ko` のように組み合わせることもできます。

タグ push の Release には、上の 6 版（`en` は `intl` パック）がすべて SHA-256 と出どころ証明付きで添付されます（`scripts/build-release.mjs`）。

フォントの埋め込みは自前で実装しています。@pdf-lib/fontkit 標準のサブセット機能は BIZ UD フォントで文字の形を壊すためです。cmap (3,1)、`/Length1`、`ABCDEF+` 名を揃え、ほかの閲覧ソフトでも警告なく表示・検索できるようにしています（`npm run check-font` でフォントの構造を検査。Acrobat での確認はまだ行っていません）。

## リポジトリ運用

- このリポジトリには、リリースごとに 1 つのコミットを置きます（日々の開発は別の場所で行い、リリースのときにまとめて反映します）。Issue とプルリクエストは歓迎します。取り込んだ変更は、次のリリースのコミットに入ります。
